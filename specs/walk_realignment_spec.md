# 游走设计对齐 Spec(2026-09-11,用户裁决:停止地鼠修补,回归原始设计)

## 原始设计(四支柱)

1. **路径纪律**:给定关系 r,从中心实体出发,寻找**以中心为起点、
   最后一条关系为 r** 的路径。
2. **模式路径**(多中心 CPU 爆炸的解):先在纯关系层找出符合要求
   (以 r 结尾)的模式路径,再以实际中心实例化重走。
3. **路径一致性**:每个实体不仅满足当前三元组,还必须满足**下一跳
   的关系**才能保留(前向验证,剪掉结构性不完整路径)。
4. **CVT 双设计**:
   a. **路径驱动的展开义务**:模式路径的末跳命中提交关系时,若命中
      的节点是 CVT、或最终实体**之前**的节点是发出核心关系的 CVT,
      则该 CVT **必须展开**(事件节点不是答案,属性才是世界——未展开
      的裸 m.xxx 违反行契约);
   b. **top-K 是 per-CVT 的属性排序**:对**该 CVT 自己的属性键**
      (通常 2-5 个)按(子)问题 GTE 排序,超出的才裁;提交关系的
      组件豁免/置顶(4b 命中键优先)。**不存在"case 级属性键词表排序"**
      ——一个 CVT 节点不可能有 143 个属性(48 case 实测:97% CVT ≤5 键,
      74% ≤2 键;"平均 96 键/case"是跨 CVT 聚合假象,洪泛治理对象是
      少数多键 CVT 与跨 CVT 重复,不是键的全局配额)。

## 2026-09-12 4a 实现偏差裁决(用户:先对齐 spec,再改代码)

- **实现偏差**(2026-09-08 引入,当时记录为"每 case 一次键排序"):
  `_cvt_key_rank` 对 **case 级全部属性键词表**(48 case 实测 96-190 个)
  做 GTE 排序,cvt_disp 只显示全局 top-5 键 ∪ 提交组件。
- **违反设计的后果**:单 CVT 仅有的 1-2 个信息键若全局排名 6+ →
  括号被滤空 → 裸 m.xxx(1392 标本:`institution` 全局 #7,答案
  The New School 不可见;判别键 `number`=3565 与 GTE #1 的
  `number_of_postgraduates` 字面不同,同样滤空)。
- **临时止血**(2026-09-12 已上,afead4c):cvt_disp 过滤后为空时按
  GTE 序回退显示该 CVT 自身前 3 键(never-blank)。48×3:hit 72.9→76.4,
  f1 0.598→0.644。**这是补丁不是对齐**——per-CVT 语义下空括号不可能
  发生,重实现时应移除。
- **对齐重实现方向(待批准后实施)**:
  1. 键排序域改为 per-CVT:对每个出现的 CVT 的自身键集(≤10 个)排序
     ——可直接用已有 case 级 GTE 排名作为**键序参考**(键的相对序),
     但**准入域=该 CVT 自己的键**;或每 CVT 一次轻量排序;
  2. top-K 只对 >K 键的 CVT 生效(实测 3%);洪泛治理重心移回
     CVT-尾压缩(≥4 尾折叠)与族键值 cap——它们管的是"多少值",
     键闸管的是"哪些键",两层不要混;
  3. 提交组件豁免/置顶(4b)语义不变;
  4. never-blank 回退删除(设计下无意义);
  5. 验收:1392 标本答案键可见;25/1171 标本不回归;48×3 对照 76.4%。

## 对齐实施

1. **多步模式接入**(支柱 1+2+3 一体):提交的家族在中心无 1-hop 直连
   支持时,用 pattern 索引找出"中心→…→家族终点"的 ≤2 命名跳模式
   (CVT 透明),以**多步 step_relations** 提交游走——前向验证自动生效,
   RPE 兜底退回弱覆盖条件(n_steps>1),路径纪律由引擎原生保证。
2. **桥退役**:多步模式接管到达功能;桥不再进 rel_idxs(终止地位
   消失),echo 保留审计。SEQ_BRIDGE_TERMINAL 默认翻 0。
3. **CVT 命中键置顶**(支柱 4b):cvt_disp/_cvt_attr_display 的键序:
   提交族命中键 → GTE 问题键 → 其余(现在是"豁免进集",改为"置顶")。
4. 验收:48×3 A/B vs topk5(0.6802/82.6%);mismatch 应保持 ≤5
   (多步模式接管到达);hub 渲染体量应缩(award 终止段消失)。

## 历史判决链(全部保留供回溯)

五次收紧实验(免桥/降级/标注/遍历-only/提交终止准入)均负收益的
统一解释:n_steps=1 下 RPE 的到达能力只有"松终止"一条腿;多步模式
恢复后,到达与纪律不再互斥——这是本 spec 的赌注与验证点。

## 2026-09-12 修正:多步判决被展示过滤污染 + 路径级准入(已实施)

**取证结论**(SESSION_MEMORY 2026-09-11 realign5 条目,闭环复现):
realign/realign2/4/5 全量判决里的"多步到达不足/mismatch 48-76"并非
到达问题——游走与逐跳实例化成功(标本验证 137-222 条三元组),是
`_display_license_filter` 的**逐边准入规则**(旧架构:实体游走→事后
归纳)把模式路径的中间跳判为"漂移",连锁滤空全部证据,误报
RELATION_MISMATCH。上述判决链中引擎多步的负结论需以修复后配置重测。

**用户裁决(准入单位=路径)**:模型提交的是**末尾关系**;要评估的是
**路径**——"某条路径的最后一跳是提交关系"即为合法,而非把路径上
每一跳单独对照提交关系逐边评估。过滤发生在游走完成之后,看的是
最终路径。

**已实施**(`_display_license_filter` path_mode,treq.multistep 非空时
激活):路径末跳 ∈ 提交关系(全名/typed 名)或端点 CVT → 路径合法,
路径全体节点随路径入 lic;渲染路径列表按同一末跳判据过滤。普通调用
(站立配置)保持旧规则,字节级不变。验证:BT0+MM 标本 sg2/sg4 由报错
转为证据(候选含 Eastern Time Zone);站立四调用输出 diff 为空;
144 测试全绿。

**遗留**:排序 support 优先(GTE 二次排序未接,C 段无 IO)。
